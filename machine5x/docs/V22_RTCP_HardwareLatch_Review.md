# V22：Physical17 RTCP + ECI3808 五轴同沿位置锁存复核与集成说明

> 项目：MotionLaserSync / XYZ-C-B 五轴线激光扫描
>
> 版本目标：在 V21 的五轴关节空间 SP 缓冲执行、17 参数标定/点云重建基础上，增加用于线激光扫描轨迹研究的软件 RTCP；同时把采集协议改为 ECI3808 IN0 硬件位置锁存，不再采集或使用 C/B DPOS。

## 1. 结论先行

V22 的运动与测量链路统一为：

1. **任务空间规划**：以传感器坐标系内选定的受控点（默认传感器原点）在机床坐标系中的 XYZ，以及 C/B 姿态角，描述扫描任务。
2. **Physical17 RTCP 逆解**：直接调用与单球标定、点云重建相同的 17 参数五轴模型，不复制第二套名义运动学；在给定 C/B 时求使受控点达到目标 XYZ 的 X/Y/Z。
3. **自适应离散**：按照受控点弦误差、旋转步长和直线轴步长细分任务段，得到高密度 XYZCB 关节折线。
4. **ECI3808 执行**：沿用 `MoveAbsSp` 五轴 BASE 缓冲，把每段的起始/运行/结束速度随段进入控制器队列。
5. **硬件同步采集**：每次采样前五轴均执行同一 R0 锁存配置；OUT14 的一个高速 NPN 电气沿同时送到传感器触发输入和 ECI3808 IN0/Latch A；五轴 MARK 均有效后读取 `REG_POS(1..5)`。
6. **点云重建**：逐轮廓用同一 Physical17 模型和锁存 XYZCB 计算 `T_MS`，再把传感器二维轮廓变换到机床坐标系。

V22 不再在 TABLE 中保存 `DPOS(C)`/`DPOS(B)`，上位机实际扫描姿态也不读取 C/B DPOS。C/B 姿态统一使用编码器反馈 MPOS（硬件锁存时为 REG_POS 中的反馈位置）。

## 2. RTCP 的任务定义

本机床有 5 个独立运动自由度：

\[
q=[X,Y,Z,C,B]^T.
\]

因此不能要求任意六自由度的传感器位姿。V22 的 RTCP 任务量定义为：

\[
y=[p_x,p_y,p_z,C,B]^T,
\]

其中 `p=[p_x,p_y,p_z]^T` 是传感器坐标系中某个固定受控点 `p_S^*` 在机床坐标系中的期望位置。默认：

\[
p_S^*=[0,0,0]^T,
\]

也可以通过 `Rtcp17Options::controlledPointSensorMm` 指定激光平面内的某个参考点，例如 `[0,0,95] mm`。

完整正运动学仍为标定模型：

\[
p_M=f(q,\theta_{17},p_S^*),
\]

其中 `theta_17` 同时包含 XYZ 非正交、B/C 轴实际轴线和完整 6DoF 手眼关系。

## 3. 为什么 V22 的 RTCP 逆解可以精确求 X/Y/Z

对固定 C/B 而言，当前 Physical17 模型对三个直线轴坐标仍是仿射的。代码不硬编码这个仿射矩阵，而是通过统一的 Physical17 前向模型数值构造三个单位基：

\[
p_0=f([0,0,0,C,B],\theta),
\]

\[
u_X=f([1,0,0,C,B],\theta)-p_0,
\]

\[
u_Y=f([0,1,0,C,B],\theta)-p_0,
\]

\[
u_Z=f([0,0,1,C,B],\theta)-p_0.
\]

令：

\[
A=[u_X\;u_Y\;u_Z],
\]

则目标受控点 `p_d` 对应的直线轴坐标通过：

\[
A
\begin{bmatrix}X\\Y\\Z\end{bmatrix}
=p_d-p_0
\]

直接求解。因此这里没有把误差模型降回名义 `Rz(-C)Ry(-B)`，而是使用全部 17 参数。

实现位置：

- `include/runtime/Rtcp17.h`
- `src/runtime/Rtcp17.cpp`
- `Rtcp17Model::inverseControlledPointAtAngles()`

每次逆解后都会再进行一次 Physical17 正解检查；默认要求逆解/正解一致性残差不超过 `1e-8 mm`，否则拒绝该 RTCP 目标。

## 4. 自适应 RTCP 折线与误差控制

控制器最终仍需要 XYZCB 关节段，因此任务空间线段采用递归二分。对一条任务段的两个端点逆解得到 `q_a, q_b`，然后检查关节中点：

\[
q_{lin}=\frac{q_a+q_b}{2}.
\]

真实期望任务中点为：

\[
p_d(1/2)=\frac{p_a+p_b}{2}.
\]

计算 Physical17 前向误差：

\[
e_{chord}=\|f(q_{lin})-p_d(1/2)\|.
\]

满足以下全部条件才允许该关节段直接下发：

- `e_chord <= tcpChordToleranceMm`，默认 `0.002 mm`；
- `max(|ΔC|,|ΔB|) <= 0.10 deg`；
- `max(|ΔX|,|ΔY|,|ΔZ|) <= 0.50 mm`。

否则继续二分。这个机制特别适合后续研究扫描曲线：上层可以替换任务轨迹生成器，而底层 Physical17 逆解与控制器执行层不需要重写。

## 5. 速度语义

### 5.1 G94

对有 XYZ 任务位移的 RTCP 线段，`F` 按任务空间受控点速度（mm/min）解释。任务段名义时间为：

\[
T=\frac{L_{TCP}}{F/60}.
\]

纯 C/B 姿态变化且受控点保持不动时，没有 TCP 距离，V22 明确采用旋转任务量的 deg/min 语义计算名义时间。

### 5.2 G93

`F` 为逆时间：

\[
T=\frac{60}{F}.
\]

RTCP 自适应细分后按照任务参数比例把这个总时间分给各控制器段。

### 5.3 控制器轴限制仍是最终约束

任务空间时间不是强行突破电机能力。下层 `FiveAxis::plan()` 仍检查每个 XYZCB 轴的速度、加速度、减速度和软件限位。若给定时间不可实现，G93 会直接报错；普通 G94 在满足轴约束时可能被安全地拉长实际控制器时间。GUI 会同时报告“任务空间名义时间”和“控制器规划时间”。

当前版本不是 jerk-optimal/NURBS RTCP，也不声称任意尖角能够无限制不停速。RTCP 折线标记为 `continuous=true` 后，只允许小角度、同向关节段保留受限连接速度；更大或反向拐角仍减速/停速。

## 6. G 代码集成

V22 增加：

- `G43.4`：启用 Physical17 软件 RTCP；
- `G49`：关闭 RTCP；
- `G92`：RTCP 模式下建立任务空间局部锚点，不改控制器 DPOS/MPOS；
- `G00/G01/G02/G03/G05`：在 G43.4 模式下进入 RTCP 任务空间路径生成。

示例：

- `examples/v22_rtcp_line_scan.nc`
- `examples/v22_rtcp_orientation_hold.nc`

### 6.1 单球 3D 平移 gauge 与绝对 RTCP

单个机床坐标未知球只能使 17 个物理参数获得 rank 14 信息；全局三维平移仍有 gauge。因此 V22 不允许把一个任意 gauge 下的手眼平移误当成机床绝对 RTCP 坐标。

如果 `absoluteGaugeKnown=false`：

- G91 相对 RTCP 可以运行；
- G90 绝对 XYZ 在没有外部绝对基准时必须先用 G92 建立本次程序的局部任务坐标锚点；
- 若后续通过已知机床球心、外部测量或其他基准锁定真实绝对手眼平移，则可把 `absoluteGaugeKnown=true`。

## 7. ECI3808 五轴硬件锁存方案

### 7.1 采用的硬件资源

ECI3808 硬件手册明确：

- IN0、IN1 是高速输入，其中 IN0 支持 Latch A、IN1 支持 Latch B；
- 锁存通过 `REGIST` 配置，并通过 `REG_INPUTS` 映射；
- OUT14、OUT15 是高速 NPN 输出；OUT14 在 PWM 关闭时也可作为普通高速输出。

ZBasic 位置锁存资料还给出了同一硬件输入锁存多轴的做法：对每个轴分别 `REGIST(mode) AXIS(axis)`，全部轴使用同一 R 通道和同一硬件输入，然后等待各轴 MARK 并读取各轴 REG_POS。

### 7.2 V22 物理时序

推荐接线概念：

```text
              ┌──> scanCONTROL Trigger In
ECI OUT14 ────┤
              └──> ECI IN0 / Latch A
```

这是“同一个实际电气沿同时服务两个设备”的方案。根据传感器触发输入的电压、电流、隔离和地参考要求，实际接线可能必须增加隔离器、光耦、开漏/电平转换器；**不得在没有核对 scanCONTROL 电气规格时直接短接。**

每个 5 ms 名义周期：

```text
REGIST(4) AXIS(1..5)
        ↓
OUT14 ON  ─────→ 同一低有效电气沿 ─────→ 激光触发 + ECI IN0
        ↓
等待 MARK(1..5)
        ↓
REG_POS(1..5) 写入 TABLE
        ↓
OUT14 OFF
        ↓
发布 writeIndex / triggerCount
```

当前默认 `REGIST(4)` 是按官方脉冲轴示例中“24V → 0V”的 R0 锁存用法选择的。官方资料同时提醒，上/下降沿是控制器内部状态概念，实际输入类型可能不同，因此**上机必须用 ZDevelop/RTSys + 示波器确认真实有效沿**。如果实机证明 mode 3 才对应所需电气沿，应统一修改 BASIC 和 PC 协议常量，不能两端不一致。

### 7.3 V22 TABLE 协议

协议 magic：`220608`，记录维度由 V21 的 8 改为 6：

```text
ordinal,
X_REG_POS,
Y_REG_POS,
Z_REG_POS,
C_REG_POS,
B_REG_POS
```

不再存在：

```text
C_DPOS
B_DPOS
```

TABLE 空间为 1600 float，header 从 330 开始、数据从 350 开始，容量 208 条：

\[
350+208\times 6=1598<1600.
\]

帧元数据的来源位掩码为：

- `feedbackMask=24 (0b11000)`：C/B 是编码器反馈来源；
- `commandMask=7 (0b00111)`：XYZ 在当前 ATYPE=1、无独立反馈编码器配置下是控制器规划位置来源；
- `latchMask=31 (0b11111)`：五个位置由同一硬件锁存沿捕获；
- `PoseTiming::HardwareLatched`。

## 8. 为什么 XYZ 的 REG_POS 与 C/B 的 REG_POS 物理意义不同

V22 当前硬件配置：

- X/Y/Z：ATYPE=1，脉冲轴，没有在项目中使用独立编码器反馈；
- C/B：ATYPE=4，步进/伺服 + 编码器反馈。

ZMotion 的锁存资料说明，对无反馈脉冲轴，REG_POS 可得到控制器位置（其 MPOS 没有独立测量意义，实际相当于 DPOS 被复制到锁存位置）；对有反馈轴则锁存真实 MPOS。

因此 V22 的“同沿”含义是时间同沿，而不是声称五个轴全部具有同等物理反馈传感器：

```text
XYZ: 同沿锁存的控制器规划位置
C/B: 同沿锁存的编码器反馈位置
```

如果以后 XYZ 也接入可靠编码器并配置相应 ATYPE/反馈，则同一协议可以升级为五轴反馈锁存，但必须重新验证控制器参数和轴误差模型。

## 9. 上位机彻底移除 C/B DPOS 依赖

V22 做了两层处理：

1. 硬件采样 BASIC 不读取、不传输 C/B DPOS；
2. 常规上位机状态读取中，C/B 只调用 `GetMpos`。为了不破坏大量历史 UI 结构，旧 `dpos.c/dpos.b` 字段只做 MPOS 的兼容别名，不再产生真实 `GetDpos(C/B)` SDK 调用。

五轴轨迹的起点、G 代码完成判定、RTCP 起点、扫描重建都采用：

```text
X,Y,Z = DPOS
C,B   = MPOS
```

## 10. 数值仿真

仿真使用完整 Physical17 误差模型和非零手眼变换。

### 10.1 RTCP 直线

给定一个任务空间直线，同时让 C/B 从起始姿态变化到终点姿态：

- RTCP 生成控制器段数：512；
- 对每个控制器段内部再采样多个点，最大受控点直线误差：`7.324369e-05 mm`；
- 若仅把 RTCP 两端的 XYZCB 直接做关节直线插补，最大任务空间偏差：`17.9868876 mm`。

### 10.2 纯姿态变化，受控点保持不动

同一个起始姿态，只改变 C/B，要求传感器受控点位置固定：

- RTCP 最大采样漂移：`7.325412e-05 mm`；
- 不做 RTCP、XYZ 不补偿时最大漂移：`66.3170922 mm`；
- RTCP 为此产生的 XYZ 总补偿量：`66.3160325 mm`。

### 10.3 硬件锁存记录的 binary32 量化

把一个同沿五轴姿态先量化成控制器 TABLE float，再按 V22 六字段协议解码：

- 最大关节量化误差：`1.652393e-06`（对应轴的用户单位）；
- 经 Physical17 传播到受控点的误差：`1.733868e-06 mm`。

仿真中的“20/40/60/80/100 µs 顺序读取延迟”只用于说明顺序采样敏感性，并非 ECI3808 实测。该假设下混合姿态造成 `0.00340591 mm` 的 TCP 偏差。真实 OUT14→IN0、OUT14→传感器以及曝光中心延迟必须上机测量。

原始结果：`verification/v22_rtcp_latch/summary.json`。

## 12. 实机部署的必要验收顺序

1. **禁能/空载状态编译 BASIC**：在目标 ZDevelop/RTSys 和目标固件上编译 `controller/ECI3808_5Axis_Controller.bas`，检查 4KB 程序空间、TABLE、REGIST、TIMER/中断语法。
2. **只测 IN0 锁存，不接传感器**：用手动或测试脉冲确认 `REGIST(4)` 对应实际希望的 24V→0V 电气沿；同时观察五轴 `MARK` 和 `REG_POS`。
3. **测 OUT14→IN0 回环**：示波器同时看 OUT14 与 IN0，确认脉宽、传播延迟及边沿方向。
4. **接入传感器前确认电气兼容**：检查 scanCONTROL Trigger 输入允许的电压、电流、开漏方式和公共地；必要时加隔离/电平转换。
5. **测 OUT14/IN0/传感器曝光三者时间**：至少得到 `t_latch - t_trigger` 和 `t_profile - t_trigger` 的均值、峰峰值和重复性。
6. **静态锁存验证**：静止 XYZCB 下连续采样，所有 profile ordinal 与锁存 ordinal 一一对应。
7. **单轴低速动态验证**：分别只动 X/Y/Z/C/B，验证点云中不存在明显速度相关位姿偏差。
8. **五轴 RTCP 空运行**：先关闭传感器，在无工件碰撞风险下运行 `v22_rtcp_orientation_hold.nc`，通过外部测量/示波器观察 XYZ 补偿和 C/B 反馈。
9. **低速 RTCP 扫描**：从非常低的任务空间速度开始，比较重复扫描、正反向扫描及不同姿态的同一几何体。
10. **生产放行前**：验证急停、限位、断网、TABLE 溢出、锁存丢失、传感器丢帧、暂停/恢复及 RTCP 软限位。

## 13. 当前仍然明确保留的研究接口

V22 已经把“运动学正确性”和“硬件同步正确性”的基础层搭好，但后续线激光扫描轨迹研究仍可以继续增强：

- 根据曲面法向规划 C/B，使激光平面与表面满足入射角/遮挡约束；
- 以激光条纹覆盖率而不是单个受控点作为规划目标；
- Jacobian 条件数、奇异位形和 C/B 回绕/最短路策略；
- TCP 恒速与曝光频率耦合，使相邻 profile 在工件表面等距；
- 曲率自适应采样；
- 更高阶的速度/加速度/jerk 前瞻；
- 碰撞检测和轴行程优化；
- 若 ECI3808/固件支持合适的硬件位置比较输出，可进一步研究“按路径长度触发 profile”，减少定时触发造成的空间采样非均匀。

这些功能可以在新的任务轨迹层实现，底层 `Rtcp17Model`、Physical17 标定结果、五轴 SP 队列和硬件锁存帧格式无需推倒重来。

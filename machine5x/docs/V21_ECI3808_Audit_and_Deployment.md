# V21：ECI3808 五轴项目审计、修订与部署报告

日期：2026-09-08。输入基线：本次会话提供的 `5Axis_project_v20_2_physical17_rank14.zip`，并对照原 V20.1 项目及用户提供的《ZMotion PC 函数库编程手册》2.0。

## 1. 交付结论与适用边界

本次不是只增加两个界面坐标，而是修改真实调用链：

```text
G 代码/点列 → 五轴关节目标 → 预检/限速 → ECI3808 五轴 SP 运动缓冲
                                                   ↓
BASIC 数字触发 → TABLE 五轴记录 → 轮廓序号配对 → 冻结本次标定/偏移
                                                   ↓
                 SingleSphere17Model FK → 世界点云 → 带来源的归档/重放
```

完整原工程与第三方库已保留。新的独立数值模块同时被 GUI 构建目标和离线测试引用，不是两套互不相关的算法。实际修改的 `ZmcController.cpp`、`SyncManager.cpp` 在模拟 Qt/SDK 传输环境中编译并运行。

**可以确认：本交付的可移植核心、模拟 SDK 路径、协议逻辑、数学与归档负载通过下述测试。不能确认：Windows Qt/VTK 实际编译链接、真实 Qt 事件循环/线程行为、ZDevelop 对 BASIC 的原生编译、目标固件支持和实机精度。** 不把“源文件存在”“source-contract 通过”写成“完整 GUI 已运行”。

仍须明确四个边界：

1. 当前 BASIC 是数字触发后顺序读五轴，**不是五轴同时硬件锁存**。XYZ 仍是 DPOS 指令位置；不能将其标注为已测得的真实 XYZ 编码器位置。
2. 连续运动是五轴关节空间 SP 缓冲插补。共线同向连接允许非零连接速度；任意非共线连接采取保守精确停速。没有任意拐角不停速、TCP 恒速、RTCP、NURBS、完整跃度约束或碰撞检测。
3. 17 物理参数及手眼关系保留，但未知球标定的平移规范问题仍存在。扫描结果可保持同一规范下的内部一致性，不能直接声称获得绝对机床坐标精度。
4. 旧三轴数据本来没有同步 C/B、模型或手眼信息，不能通过升级软件恢复丢失的信息。历史导入保留其几何含义，不伪造五轴来源。

## 2. 资料依据：型号能力与 PC 库接口不能混为一谈

用户手册的第 2.5 节说明 BASE 第一轴为插补主轴，参数为合成运动参数；连续运动依靠缓冲与 MERGE，SP 速度参数随运动入缓冲。第 2.4 节同时说明一般轴参数修改全局生效。因此，逐小段改全局 SPEED 并不等价于给已排队的每一段附带速度。

厂商的 ECI3808 产品页明确列出多轴插补。ECI3808 用户手册 V1.6.1 第 9 页规格表列出 128 运动缓冲、1600 数组空间和 4 KB 程序空间。本版据此限制 TABLE 地址至 1597，而不是照搬更大 ZMC 型号的存储容量。**128 是资料规格，运行时仍实际读取剩余缓冲，不能写死认为它一直空闲。** BASIC 源文件大小不等于编译后的程序空间占用；4 KB 是否足够必须由目标 ZDevelop/固件实际编译确认。

ECI3808 手册第 20 页注明 IN0/IN1 支持锁存 A/B，但这不能单独证明原接线能同时锁住五轴。第 30 页轴接口表列出 OUT16/18/20/22/24/26/28/30 使能功能；不能因为通用输出表是 16 点就把原项目 OP24、OP26 当成不存在而删除。它们是否确实连接本机 C/B 使能，仍以接线记录为准。

用户手册第 10 页明确提示 ECI 的特殊信号有效状态与 ZMC 不同。本次没有擅自反转原点、限位输入的极性；必须实测各输入、使能、急停以及断线状态。原项目轴 1～5 的机械比例和接线仅作为基线保留，不视为已经替用户验收。

**接口版本：** 用户手册 2.0 的一些原型属于旧版，且有名称/注释排版问题；本项目编译使用包内 `third_party/zmc/include/zauxdll2.h`。实际五轴 `ZAux_Direct_MoveAbsSp` 调用传轴列表与位置列表，不能为了匹配旧书示例删掉当前 SDK 必需的参数。SDK 返回 0 才算调用成功，非零进入错误/停止流程。

## 4. 控制器五轴协议与同步的真实含义

### 4.1 固定轴序与量纲

机床/软件数组统一为 `XYZCB`，控制器分别为轴 1、2、3、4、5。XYZ 为毫米，C/B 为角度，不是弧度。内部几何误差旋转参数仍遵从原 17 参数模型的弧度定义，不能把关节角单位直接套到误差参数上。

原硬件配置保留：XYZ UNITS=4000，C=1112，B=5560；XYZ ATYPE=1，CB ATYPE=4。C/B 绝对编码器初始化产生的机械偏移在每次采集会话中冻结。下发指令：`controller_target = mechanical_target - rotary_offset`；采样还原：`mechanical = raw + rotary_offset`，只加一次。

BASIC 启动先取消运动、关触发、关原 C/B 使能输出，不自动使能驱动器。**源码保留的比例不是新测量结果，必须核对齿轮比、脉冲倍频、编码器方向和 UNITS 实际读回。**

### 4.2 TABLE V21 ABI

头部 330～349；数据起点 350；每记录 8 个 float；156 槽，环形缓冲留空一槽，最多 155 条未消费记录；最大地址 1597。默认定时 5 ms。

| TABLE 地址 | 意义 |
|---|---|
| 330 / 331 / 332 | 容量 / 写索引 / PC 读索引 |
| 333 / 334 | 故障码 / enable：0 关闭、1 连续、2 单探针 |
| 335 / 336 | ISR 发布计数 / 触发计数 |
| 337 / 338 / 339 | magic=210517 / 维度8 / 周期5ms |
| 340 / 341 / 342 | 请求会话 / ACK 会话 / PC 心跳 |
| 343 / 344 | 反馈位掩码24 / 时序类型1 |
| 345～349 | 保留 |

数据顺序：`ordinal, X_DPOS, Y_DPOS, Z_DPOS, C_MPOS, B_MPOS, C_DPOS, B_DPOS`。

BASIC 先检查空间、会话、心跳、序号上限；再输出触发、顺序采样、撤销输出；最后发布写索引和计数。PC 跨环读取完整成功才推进索引。ACK 结果不确定时不盲目重试。序号上限16777214，避免继续自增到 binary32 无法逐整数区分的范围。数据完整性故障停止运动与触发，不用当前姿态补丢帧。

启动顺序：关闭采集 → 请求新会话 → 等待控制器清空并 ACK → 输出恰好一个探针 → PC 校验该探针对应一条轮廓/位姿 → 才继续模式1。最终停采集还要排空和对账，M60 不跳过最终完整性检查。

### 4.3 精度限制不能由软件措辞消除

顺序读 DPOS/MPOS 和 OP 脉冲的宽度、采样先后、传感器触发至曝光延迟需要示波器/逻辑分析仪实测。155 槽在名义200Hz下约容纳0.775秒未消费数据，但不构成实时服务保证。PC 心跳超时保护也不替代独立急停或安全回路。

记录 `feedbackMask=24`（仅 C/B 位是反馈）、`ControllerSequential` 等时序标记；不命名为“五轴同沿真实编码器位置”。软件轮询模式进一步标为 `SoftwareInterpolated`：只有接收时刻附近有效前后括号才插值，拒绝外推，并处理尾帧排空。它也不是曝光时刻同步。轨迹角度使用机械连续坐标而非擅自取模寻找短路；是否允许多圈要由本机限位明确决定。

若要求动态五轴测量级精度，仍需确认统一触发下的多轴 REGIST 能力、实际编码器接线及传感器延迟；资料本身没有给出这台机器已满足它们的证据。不能把这一硬件问题伪装成新增五个读取函数就解决。

## 5. G 代码和连续插补

### 5.1 本工程支持的方言

支持 G0/G1 五轴关节运动；G2/G3 圆弧加其余轴线性变化；G17/G18/G19 为 XY/ZX/YZ；IJK 为相对圆心，支持 R、IJK 整圆与原 XY 三点 P/Q；G90/G91；G21；G92 程序偏移；G93/G94；G4 的 P 是本项目约定的整数毫秒；G5 为后接关节点列。支持 M0、M2/M30、M50/M51、M60～M63。`S0/S1` 是采集标记，不是主轴转速。

未列出的代码明确报错，包括 G43.4、G54 等，不能声称是完整通用数控解释器。同一块不支持 G/M 混写；路径字符串需要双引号。旧 XYZ 行仍可用，未出现的 C/B 保持原位置，不强制回零。

G94 下，XYZ 有位移时 F 为毫米/分钟；纯转动采用本项目的度/分钟约定，并分别受 C/B 限制。没有显式 G93/G94 的旧程序维持本项目原每秒约定，仅为兼容；新程序应明确写 G94。G93 是每分钟倒数进给，必须逐运动块给 F，并将加减速时间纳入可行性检查；不可能满足的时间要求拒绝，而非悄悄超速。

### 5.2 如何给 ECI3808 发连续运动

先将全部目标解析成机械 XYZCB，再检查完整路径的有限性、轴限位和限速。实际读回的控制器软限位与主机配置取交集。圆弧在 PC 离散为小关节段，当前默认弦误差0.01mm、转轴步长0.25deg；这里约束的是所定义的 XYZ 圆弧和关节变化，不是带旋转手眼偏置后的 TCP 轮廓误差。

运行设置五轴 BASE、全部 INTERP_FACTOR=1、MERGE=1；整个规划的矢量 ACCEL/DECEL 一次设置。SP 每段附带 STARTMOVE_SPEED、FORCE_SPEED、ENDMOVE_SPEED。PC 分批补缓冲（低水位16、高水位48、单次最多8段），同时查询控制器实际容量，给采集读表和停止保留通信机会。SDK 失败立即清除当前及缓存运动，不继续假装轨迹已成功下发。

当度与毫米共同进入控制器合成范数时，主机用该合成量作为**参数化坐标**，再逐轴投影限制速度/加速度。它不是物理长度。特别是非零手眼偏移、转轴倾斜、摆头运动下，不能据此宣称 TCP 恒速。

非共线连接处矢量方向不连续，当前保守设连接速度为零；共线同向连续通过。不是把所有段都零速，也不是不经约束就高速过拐角。实际传输带宽不足会造成缓冲饥饿和停速，因此高速/密集小线段连续性能仍需上机测量。

### 5.3 暂停、停止及示例

暂停真正发送 MovePause，恢复发送 MoveResume，不从当前位置重新执行增量块。停止、故障或断开清理主机待发队列与控制器五轴运动缓冲。单步执行不批量吞掉下一块。等待运动完成检查全部轴状态、命令终点与 C/B 反馈稳定性，不只看 XYZ。

`examples/` 有三个手工调试示例和四个 GUI 实际加载模板。GUI 不再生成另一个隐藏版本的三轴模板。模板均显式采用 G94、起始 M0，说明必须先确认起点/工件/摆头包络；相对小位移也不构成“天然安全轨迹”。`v21_g05_and_arcs.nc` 含绝对原点定位，仅在人工确认该位置可达无碰撞后使用。

## 6. 统一运动学与点云来源

所有扫描帧通过 `SingleSphere17Model::sensorToMachineTransform` 得到 T_MS：

```text
p_M = T_MS(q_mechanical, theta_physical17) * [x_sensor, 0, z_sensor, 1]^T
```

名义模型沿用 V20.2 的 `Trans(XYZ) Rz(-C) Ry(-B) T_ES`。真实轴线位置/倾斜、XYZ 非正交与完整手眼由原模型负责。不再额外套旧三轴的轴交换、安装平移或固定姿态偏移；不能“双重校正”。

每次采集必须显式应用一个成功求解/加载的17参数结果。运行时禁止悄悄换模型；每帧冻结模型与转轴偏移，避免扫描中界面变化让同一文件前后使用不同定义。GUI 默认标 `absoluteGaugeKnown=false`。是否能将该位改为 true 必须有外部基准证据，不因文件含一个4×4矩阵就自动成立。

这次没有重写原标定目标函数，也没有重新把物理结构缩为14维。原14和17参数标定回归仍通过。新的运行时仿真使用已知的完整误差模型测试重建/保存链，**不是该仿真重新辨识了全部17个物理真值**。

## 7. 保存与重放

### 7.1 五轴帧元数据

每帧包含 session、ordinal、轮廓索引、传感器/主机时间、时序类别、反馈来源掩码、机械关节XYZCB、命令关节、原始读数、C/B偏移、完整双精度 T_MS、17参数以及绝对规范是否已知。每个点保留原轮廓点索引和二维 x/z；世界坐标可以重算。

CSV 使用17位有效数字输出上述信息。M60 即使选择 PLY，也额外生成 `.poses.csv`；PLY 本身仍是几何交换格式，不能单靠它恢复17参数和关节。空轮廓的位姿保存在伴随位姿文件中，不能让“没有有效点”把序号链断掉。全部为空的扫描不自动报告 M60 保存成功。

### 7.2 v3 格式与兼容

新增 `ScanArchive5D` 可移植二进制负载：版本化、小端、双精度、CRC32、长度/计数限制、有限数值验证、点索引检查、T_MS 与模型/关节一致性检查。当前单文件负载上限512MiB，大扫描应分块。不会再以 int16 静默截断大范围二维坐标。

Qt `.scan` 是该负载的带文件头封装，v3 写新格式；v1/v2 保留只读兼容，不为旧文件发明C/B。新压缩标识为 QtZlib；历史 scan_lz4/scan_zstd 名称只是接受的旧输入别名，写出时不会伪标成真正的 LZ4/ZSTD。单独的 `.a5d` 是离线CLI使用的可移植负载文件，**不是可直接互换的完整 Qt `.scan` 文件**。CLI `inspect` 只接受 `.a5d`。

世界点记录在编码前复核是否与原始二维和T_MS一致；不可逆、不一致数据不作为可信五轴归档。Qt writer 使用 QSaveFile 提交；异步程序终止等待自己的保存任务。发生失败、取消、未知格式或目录不可创建时进入错误流程，不以日志警告代替失败结果。

**测试范围：** 可移植负载的编码/解码、损坏拒绝、空帧、精度保持真实执行；Qt qCompress/qUncompress、历史文件兼容导入、GUI异步保存与QSaveFile完整路径仅源审查，未在真实Qt环境运行。不要把这里的往返零误差说成所有历史`.scan`及压缩包装都已测试。文件读取有长度和CRC检查，但未宣称对任意恶意压缩炸弹完成安全审计；只使用可信扫描文件。

### 9.2 Windows完整应用

使用与原项目兼容的 MSVC x64 Qt6（Widgets/Concurrent/OpenGLWidgets）以及启用 GUISupportQt 的VTK，不能把MinGW Qt与MSVC导入库混用。SDK头文件、lib、DLL来自输入工程；必须确认实际安装/固件匹配，不能仅靠SDK函数名推断支持。

### 9.3 BASIC与硬件验收顺序

**第一阶段：不允许运动。** 备份控制器原工程、轴参数和标定结果。核对急停/驱动器STO等独立保护与五轴使能极性。用ZDevelop对 `controller/ECI3808_5Axis_Controller.bas` 编译，检查4KB程序空间、TABLE地址、TIMER/ONTIMER/DPOS/MPOS及RAPIDSTOP语法在本固件上实际可用。先RAM验证而非直接覆盖ROM自启动。旧文件名内容已同步，不能同时运行两份定时器程序。

**第二阶段：分轴低速确认。** 读回轴1～5实际ATYPE/UNITS/限位，验证正负方向、原点、轴状态。先完成C/B绝对位置初始化，再经人工允许使能；确认机械偏移只加一次。不要用“所有DPOS置零”解决位置看起来不对的问题。文件菜单加载本机实际确认的轨迹限制JSON；示例只是原工程数值，不是设备额定参数认证。

**第三阶段：静止采集与低速摆动。** 成功求解或加载17参数结果，并通过文件菜单应用到扫描。检查协议magic、8字段、反馈Mask24和session ACK，确认一个探针只生成一轮廓。实测OP0脉宽、传感器有效触发频率、曝光延迟和五轴读取相位。若探针不一一对应或计数不连续，先处理接线/传感器参数，不放宽软件匹配去“让它通过”。

**第四阶段：连续运动与数据闭环。** 先无工件或在已验证无碰撞空间运行motion-only小幅轨迹，观察C/B与XYZ共同到达、分段速度、缓冲余量；验证暂停控制器真正停下、恢复不重走增量，停止后不再补发。再试capture程序。注入网线断开、应用关闭、环满、读写失败、保存目录不可写等故障，验证及时停触发/停运动且扫描标记无效。最后用静止球、正反向和不同速度的重复扫描评估动态误差，再决定生产扫描速度。

# V27.6.6 — Physical17 独立 hold-out 验证

## 1. 为什么训练 RMS 不等于标定正确

17 参数求解使用的训练数据既用于确定参数，也用于计算训练残差。因此训练 RMS 很小只能说明模型能够解释参与求解的数据，不能证明模型在未参与求解的新 B/C 姿态上仍能正确预测。

V27.6.6 增加真正独立的第三阶段：

1. 阶段1：人工姿态，名义机床模型下求 6DoF 手眼 + 固定球心；
2. 阶段2：D-optimal 训练姿态，求 Physical17 / rank14；
3. 阶段3：重新生成与训练网格错开的姿态，另外采集 hold-out 数据，冻结模型后只评价、不再求解。

验证数据保存在 `m_validationRecords`，训练数据保存在 `m_records`。验证观测绝不调用 `m_calibrator.addObservation()`。

## 2. 如何生成真正不同的验证姿态

点击“生成独立验证姿态”后：

- B/C 网格相对训练网格偏移半个 step；
- 验证传感器目标中心使用 X={-3.5,+3.5} mm、Z={90,100} mm；
- 目标 |Y| 使用 0.25R，而阶段2训练默认使用 0.40R；
- 每个候选还必须与全部训练记录保持用户设置的最小 B/C 欧氏角距离，默认 4°；
- 默认生成 8 个独立姿态；
- 如果当前 B/C 范围跨越 0°，最终验证还要求正/负 B 和正/负 C 都有覆盖。

这不是统计学意义上的随机划分，而是面向五轴几何标定的“跨姿态 hold-out”：故意测试训练网格之间的新角度和不同视场位置。

## 3. 如何采集验证数据

最终17参数求解成功后：

1. 点击“生成独立验证姿态”；
2. 选择一行；
3. 点击现有“分段自动移动到选中计划姿态”；
4. 软件仍按 B/C 和 XYZ 子步限幅并在子步间重新找球；
5. 到位后点击“采集当前姿态为验证集”；
6. 重复直到达到“独立验证姿态数”。

普通“采集当前姿态”在验证计划期间会被禁用，避免误把 hold-out 数据泄漏进训练求解器。

## 4. 验证内部执行逻辑

点击“执行独立验证”时，程序冻结：

- 最终 Physical17 参数 `m_lastResult.parameters`；
- 最终固定球心 `m_lastResult.sphereCenterMachineMm`。

程序不会重新优化任何参数，也不会用验证数据重新拟合机床球心。

### 4.1 原始球面残差

对每个 hold-out 轮廓内点：

\[
r_{ij}=\|T_{MS}(q_i,\theta_{final})[x_{ij},0,z_{ij}]^T-c_M^{final}\|-R.
\]

统计：

- signed mean；
- MAE；
- RMS；
- max absolute residual。

### 4.2 球心预测误差

对每个验证姿态，用最终模型和固定机床球心预测：

\[
\hat c_{S,i}=T_{SM}(q_i,\theta_{final})c_M^{final}.
\]

二维 RANSAC 提供实测 `x_c,z_c,|y_c|`。Y 符号不由操作者选择，而使用最终模型预测的 signed Y 选择与其一致的分支，然后计算：

- center XZ RMS；
- center 3D RMS；
- center max error；
- X/Y/Z 平均 bias。

这里的 center XZ RMS 是主要 planner/generalization 指标；Y 在接近最大截面时对半径噪声敏感，因此 3D center error 作为诊断量而不是默认硬门限。

## 5. 默认通过门限

UI 默认：

- hold-out 姿态数：8；
- 与训练姿态最小 B/C 距离：4°；
- 球面 RMS <= 0.080 mm；
- 球面 max <= 0.250 mm；
- 预测球心 XZ RMS <= 0.500 mm；
- 如果配置范围跨过零点，则正/负 B、正/负 C 都必须有验证覆盖。

这些是当前工程的默认验收门，不是机床制造商的额定精度。最终生产门限应根据重复性实验、传感器噪声和实际工艺精度要求再收紧。

程序同时显示 `validation RMS / training RMS`，用于发现明显过拟合或某些姿态系统性失配，但暂不把这个比值作为独立硬阈值。

## 6. 数据隔离与失效规则

以下操作会使验证结论失效：

- 增加新的训练采集；
- 删除训练采集；
- 重新开始阶段1；
- 改变验证门限；
- 重新求解模型（验证记录可保留，但必须重新评价）；
- 改变 Flip / ATYPE 数据源时整个标定会话本来就会被拒绝继续混用。

新增训练数据时旧 hold-out 数据直接清空，确保不会把已经看过的验证姿态在后续训练中混成“伪独立验证”。

## 7. 对扫描/RTCP 的放行

V27.6.6 中 `scanCalibration()` 只有在：

- 最终17参数求解成功；且
- 独立验证 `passed=true`

时才返回参数。

因此“文件 -> 应用当前17参数标定到五轴扫描...”不能再仅凭训练 RMS/rank 放行。

## 8. 结果保存

最终结果 JSON 仍保存 Physical17 求解结果。

如果已经执行过独立验证，保存结果时会自动再写一个：

`*_validation.json`

其中包含：

- 验证通过/失败；
- 全局 residual / center 统计；
- 门限；
- 训练 RMS；
- 每个验证姿态 XYZCB；
- 每姿态预测/实测传感器球心；
- center error；
- 每姿态球面 RMS/max。

这样能够留下独立验收证据，而不是只保存一组“训练拟合很好”的参数。

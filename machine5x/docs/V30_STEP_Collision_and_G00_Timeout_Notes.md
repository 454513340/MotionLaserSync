# MotionLaserSync V30 — STEP 工件碰撞接入、FCL 加速与五轴运动诊断

日期：2026-10-24。此修改基于用户提供的 `MotionLaserSync_V30.rar`、`MP_ALL_POSES_CONNECTED_OFFLINE_ONLY_H3(2).nc` 和 12:16:52~12:30:59 实机日志。**不要将本次离线软件测试当作设备安全验收。**

## 一、改动清单

1. **STEP 接入第三步**：在“路径规划 → 多姿态实验扫描”导入实际零件 STEP；该工具已通过 OCCT 转成毫米三角网格并设置 CAD→机床(MCS)六维初位姿。第三步从该工具获取不可变的网格快照、原 STEP SHA-256 和位姿指纹。任何一步缺失即拒绝本次几何复核。
2. **独立碰撞场景**：`CollisionEngine::setWorkpiece()` 为导入件创建独立静态 FCL BVH，不将零件错误地跟随主轴五轴运动。按配置的机床链分别检查移动结构/扫描头与该工件；机座与工件接触不视作自行碰撞，其他现场夹具未自动导入。复核使用独立 `MachineSafetyModel`，不干扰现场球靶检查。
3. **FCL 加速**：碰撞窄相位前先执行 AABB 重叠检测；间隙检查使用 AABB 距离下界，远离 1.0mm（机床配置值）阈值时不执行高成本的三角面距离计算。相邻 NC 运动段的公共端点复用前一次的检查结果，但段内采样和最终端点均保留。检测在线程池执行，每 256 段向 UI 报告一次进度，完成后记录用时。
4. **结果绑定**：即使检测期间改变 CAD 文件内容/位姿，复核结果也不能继续使用。启动验证还会重新核对 STEP 内容 SHA-256、CAD 位姿、NC 文件散列、当前标定版本、连接会话、运动补偿状态与实际同步试采证明。
5. **第三步与第四步可完成的现场验收**：第三步PASS仅表示对已设置STEP位姿的几何检测。第四步已新增真实测量的CAD→MCS位姿一致性比较、夹具最小间隙和人工安全确认、记录留档与会话/NC/STEP绑定；所有检查通过可请求实机执行。第四步取消可单独重试，不能由NC注释放行。具体操作见 `README_V30_0_3_SITE_ACCEPTANCE_AND_BUILD_FIX.md`。
6. **运动到位判定与诊断**：原代码到位要求 XYZ 的 MPOS 残差小于 0.005mm，显著严于 `models/machine5x/machine_config.json` 规定的 0.05mm；现将所有轴到位标准与机床模型一致（XYZ 0.05mm，C/B 0.05°）。完成时仍要求五轴反馈真实空闲、完整缓冲发送和多次稳定采样，不用目标 DPOS 冒充 MPOS。MPOS 无法收敛时，空闲 3s 后中止。原规划时间 ×3+5s 超时保护仍保留，不把固定超时盲目设成无限大。
7. **提高故障可诊断性**：运动状态细分为“缓冲填充中 / 控制器仍在运动 / 控制器空闲但实际位置未收敛 / 正在确认反馈稳定”；报错同时包含计划时长、截止预算、五轴目标、实际 MPOS、控制器需求 DPOS、差值和 `allIdle` 状态。查询间隔从 20ms 调整至 50ms，减少 ECI 运动缓冲填充时的状态读取竞争。
8. **可复现实验和测试**：新增无硬件依赖的 `MotionCompletionPolicy` 单元测试，以及 `diagnose_nc_offline` 命令行工具。更新一项旧测试：解释器有意把 `OfflineOnly:true/false` 视为离线文本元数据，而真正实机许可由独立运行时检查决定。

## 三、验证结论（明确区分可测与不可测）

本环境可运行 `DIGITAL_TWIN_CLI_ONLY`，但缺少 Windows 平台 Qt6、ECI SDK、VTK、Open CASCADE 和 FCL/Eigen 开发依赖；因此不能完成 Windows GUI/FCL 完整链接，更不能连接实机做运动复测。

```sh
cmake -S . -B build-offline -G Ninja -DDIGITAL_TWIN_CLI_ONLY=ON -DTWIN_ENABLE_OCCT=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-offline -j6
ctest --test-dir build-offline --output-on-failure
./build-offline/diagnose_nc_offline '/path/to/MP_ALL_POSES_CONNECTED_OFFLINE_ONLY_H3(2).nc'
```

本轮离线编译成功，CTest **32/32 通过**；其中 `GCODE_FIVE_AXIS_MPOS_COMPLETION_AND_WATCHDOG_POLICY` 为新增测试。上述检查无法度量完整 FCL 的 Windows 实际速度，未虚报加速倍数。

## 四、Windows 项目使用与后续现场验证

1. 按原工程 Windows CMake 工具链构建，确保启用实际的 OCCT STEP 和 FCL 依赖；不要把 `DIGITAL_TWIN_CLI_ONLY` 作为完整 GUI 构建。
2. 打开“路径规划 → 多姿态实验扫描”，导入**真实被扫描件** STEP（不是项目示例 CAD），设置经过测量的 CAD→MCS 位姿；可关闭对话框（窗口被隐藏、内容仍保留）。没有该文件第三步会明确提示，无法仅凭 NC 自动恢复未知实际三维表面。
3. 重新导入原 NC 并运行“实机状态诊断”。第三步显示已检测段数与用时，遇到机床或工件碰撞即阻断。STEP 文件或摆放变更后必须重新检测。
4. **第四步可正常申请放行**：进入现场测量验收窗口填写独立实测CAD→MCS六维位姿、夹具间隙、人员和测量记录；所有阈值、夹具/防护确认及启动时只读复核通过后，软件会生成现场记录并启用“开始执行”。未通过不允许执行；取消后可点击“第4步：现场测量验收”补做，无须重做整条FCL。具体阈值和风险见 `README_V30_0_3_SITE_ACCEPTANCE_AND_BUILD_FIX.md`。
5. 在安全隔离、急停和现场防护充分的前提下，由设备人员先独立测试单轴与低速小行程运动并检查实际 MPOS、DPOS、速度、空闲状态和故障位。正式运行前验证控制器报警位、五轴使能/回零、旋转绝对位置、软限位、采集互锁、现场固定夹具；采集下一份日志验证新版细分状态，不要为了让一次运行“成功”而屏蔽超时、碰撞或配准保护。

### 注意

- 本版本使用离散路径采样和三角网格 FCL，不等同于数学意义上的连续时间严格碰撞证明；薄壁/高速段需要更细采样或连续碰撞检测，并使用经过测量的几何与安全余量。
- `minimumClearanceMm == infinity` 在阈值快速筛查中表示“没有发现比阈值更近的对象”，不是精确实测最近距离。
- G 代码离线模拟时长和控制器实际加减速计划、缓冲/伺服响应不同；不能据此直接确定 38.76s 超时的硬件根因。
- 本次没有上传真实工件 STEP，因此没有执行该件的 FCL 实测基准，也没有完成实机回归。
